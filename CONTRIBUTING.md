# Contributing

Thank you for helping improve the URLZ developer experience.

## Suitable contributions

- Documentation corrections and clearer examples.
- Additional integration examples that do not expose credentials.
- Reproducible API specification issues.
- Suggestions for improving developer onboarding.

## Before opening an issue

1. Search existing issues to avoid duplicates.
2. Remove API keys, passwords, session tokens, personal data and private URLs.
3. Include the endpoint, HTTP method, status code and a minimal reproducible request.
4. For security vulnerabilities, follow [`SECURITY.md`](SECURITY.md) instead of opening a public issue.

## Pull requests

- Keep each pull request focused on one change.
- Use clear English and executable examples.
- Do not add production credentials or user data.
- Validate JSON files before submitting.
- Explain what changed and why.

By contributing, you agree that your contribution may be distributed under this repository's MIT License.
